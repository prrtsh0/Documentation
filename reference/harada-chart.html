Embeddings & Vector Databases

the retrieval half of every RAG system
1.Set up pgvector (or Qdrant) locally with a working insert/query loop.
2.Embed 200+ messy documents with a BGE / text-embedding model.
3.Implement chunking (fixed / recursive / sentence); compare retrieval quality.
4.Implement top-k retrieval and inspect what it returns.
Embeddings
& Vector DBs
5.Add reranking (cross-encoder); measure recall improvement.
6.Store metadata + filters (source, date, tag).
7.Build a similarity-search demo (question → top 5 chunks).
8.Write comparison note: pgvector vs Qdrant vs FAISS.

RAG System Implementation

the spine project — this IS your portfolio piece
1.Pick a real, messy dataset (PDFs, CSVs, support tickets).
2.Build ingest: parse → clean → chunk → embed → store.
3.Wire retrieval + prompt + LLM into one `answer(question)`.
4.Add citations to every answer (which chunk it came from).
RAG
System
5.Handle "I don't know" — refuse gracefully with no good chunk.
6.Add conversation/history layer so follow-ups work.
7.Log every query (question, chunks, answer, latency).
8.README with architecture diagram + numbers (latency, cost, recall).

2.Build a few-shot set (5 examples); measure accuracy change.
3.Refine retrieval prompt: use ONLY provided context.
4.Add structured-output (JSON schema) for answer + citations.
Prompt
Engineering

6.Test robustness: rephrase the same question 5 ways.
7.Use the eval harness to compare prompt versions (numbers).
8.Write a personal prompt cheat-sheet.

2.Wire tools into the agent loop (LLM decides tool call).
3.Run tools in a sandbox (Docker with limits); validate outputs.
4.Add a tool-call parser that reliably extracts args.

& Tools
